# MailTester 1.6

Windows Forms, .NET 10. SMTP, POP3 и IMAP на MailKit 4.18.2; MIME обрабатывает MimeKit 4.18.2 (зависимость MailKit).

## Интерфейс

- Обзор: показатели текущей сессии, переходы к SMTP, POP3/IMAP и журналу.
- SMTP: ввод параметров, переключение видимости пароля, письмо обычным текстом, добавление нескольких вложений и очистка списка.
- POP3/IMAP: поиск по теме и отправителю среди загруженных писем, дата, безопасный текстовый просмотр, сохранение вложений.
- Журнал: единая история операций, копирование, экспорт в TXT и очистка. Содержимое хранится в памяти, не сохраняется автоматически.
- Глобальный статус и длительность операции; отмена на кнопке активной операции и в общей шапке (доступна из любого раздела).
- Светлая рабочая область, тёмное боковое меню, изменение размера окна, вертикальная прокрутка при недостатке высоты и режим PerMonitorV2.

Показатели считаются с момента запуска (число принятых SMTP-сервером писем, число загруженных сообщений, включая повторные загрузки, ошибки запущенных операций). Не являются мониторингом доставки или доступности.

## DNS / Домен и расширенная диагностика

DnsClient 1.8.0, ARSoft.Tools.Net 3.6.1 (SPF), MailKit/MimeKit 4.18.2. DNS / Домен запрашивает записи A, AAAA, NS, SOA, MX, TXT, CNAME, SRV, CAA, DS, DNSKEY, известные имена www/mail/autodiscover и служебные записи MTA-STS, TLS-RPT, BIMI и SRV, проверяет разрешение MX и известные DKIM-селекторы. На каждой строке есть рекомендации. DNSSEC не валидируется, отсутствующие дополнительные записи не обязательно ошибки. Прямое перечисление всех записей и всех поддоменов невозможно через обычные DNS-запросы; не делается AXFR или перебор имён. Выберите «Инструменты / DNS / записи имени» для дополнительных типов и точного имени.

DMARC: DNS Tree Walk (не более 8 целей), psd=y/n, организационная граница, выбор p/sp/np, strict/relaxed alignment. Учитывается fallback некорректной политики при rua; это диагностическая реализация, не сертифицированный MTA. Не пересылаются отчёты, не проверяется право внешнего получателя rua, ARC и политика принимающего сервера. DNS-ошибки могут сделать результат неопределённым. Рекомендации по RFC 9989 включают постепенный переход от мониторинга к reject, historic pct, t и psd; не копируйте шаблоны без замены параметров.

Раздел «Инструменты»:

| Режим | Ввод | Результат |
| --- | --- | --- |
| SPF | IP SMTP-клиента, envelope MAIL FROM, HELO | Рекурсивный SPF check через ARSoft.Tools.Net, лимит DNS в валидаторе 10, таймаут 30 с |
| EML | Исходный .eml, до 50 МБ, при наличии доверенные IP/MAIL FROM/HELO | Received, предполагаемый маршрут с интервалами времени, Authentication-Results, Received-SPF, Return-Path; криптографическая DKIM-проверка до 10 подписей; DMARC alignment |
| PTR / IP Blacklist | IP | IPv4/IPv6 PTR и FCrDNS; DNSBL IPv4 в Spamhaus ZEN и SpamCop с контрольными ответами, ошибки не считаются NOT LISTED |
| TLS / SSL | DNS-имя, режим и порт | HTTPS/TLS, SMTP/POP3/IMAP implicit TLS или STARTTLS; сертификат, SAN, цепь, срок, системное доверие, TLS 1.2/1.3; без AUTH |
| WHOIS / RDAP | Точный зарегистрированный домен | RDAP IANA bootstrap; WHOIS TCP 43 fallback, включая .ru/.рф/.su; дата окончания, регистрационные события, регистратор, статусы и NS при наличии |
| DNS / записи имени | Точное DNS-имя, в том числе _service | Расширенные типы записей одного имени |
| Комплексный аудит | Зарегистрированный домен, DKIM-селекторы (необязательно) | DNS/MX/DMARC, WHOIS/RDAP, TLS корневого сайта и www при наличии DNS, STARTTLS 25 до 5 MX, PTR до 10 адресов |

SPF использует явно заданные SMTP-данные, для null reverse-path введите <> и HELO. Нельзя достоверно восстановить IP SMTP-клиента и envelope из произвольного EML. Authentication-Results и Received лишь показываются, не принимаются как доказательство. DNS на момент проверки может отличаться от момента доставки. DKIM работает с оригинальным EML, не пересохранённым текстом. EML не исполняется, тело/вложения не выгружаются; при экспорте вы сами сохраняете заголовки, которые могут содержать персональные данные.

Комплексный аудит не отправляет IP входящих MX в DNSBL автоматически: указывайте реальный исходящий IP отдельно. DNSBL-запросы передают IP операторам списков; соблюдайте их правила. Публичные резолверы могут блокироваться. PTR и TLS не доказывают доставку. RDAP/WHOIS передают домен реестру; отсутствие даты не означает свободный или просроченный домен. WHOIS не шифруется, формат зависит от реестра. TLS проверяет handshake на указанном порту (не HTTP, не все IP балансировщика, не полный аудит конфигурации). Невалидные сертификаты не принимаются. Предупреждение о сроке TLS/домена за 30 дней при запуске проверки; фонового мониторинга пока нет.

### Проверка

- SPF: контролируемый домен с allowlisted IP, неверный IP, рекурсивный include/redirect и пустой MAIL FROM.
- DMARC: поддомен с наследованием, psd=n, relaxed/strict alignment, DNS failure.
- DKIM: исходный подписанный EML и копия с изменённым подписанным телом.
- PTR: публичный IP, отсутствующий PTR; DNSBL на системном и публичном резолвере.
- TLS: действующий HTTPS, self-signed/просроченный сертификат на тестовой службе, SMTP 587/465.
- WHOIS: собственный .ru/.рф и .com; сравните с кабинетом регистратора.
- DNS: корень, www, _dmarc, неизвестное имя. Запустите smoke tests отдельно.

## Подключение

| Протокол | Порт | Режим |
| --- | --- | --- |
| SMTP | 587 | STARTTLS |
| SMTP | 465 | SSL/TLS |
| SMTP | 25 | STARTTLS или Без TLS с подтверждением |
| POP3 | 995 | SSL/TLS |
| POP3 | 110 | STARTTLS (STLS) или Без TLS |
| IMAP | 993 | SSL/TLS |
| IMAP | 143 | STARTTLS или Без TLS |

При смене режима/протокола проставляется стандартный порт; его можно изменить. При пустых логине И пароле SMTP работает без AUTH (если сервер разрешает). Для получения требуется авторизация. Используйте пароль приложения, если провайдер его требует; OAuth2 пока не реализован.

Получение по IMAP открывает только INBOX с ReadOnly; POP3 не отправляет DELE. По умолчанию загружаются 25 последних по порядку сервера (1–200). Письма скачиваются целиком, без ограничения размера. HTML показывается текстом, активное содержимое не исполняется. Вложения декодируются MimeKit, сохраняются по безопасным именам без перезаписи; при ошибке часть предыдущих файлов может быть уже сохранена. Можно выбрать несколько файлов для отправки. Сетевые операции асинхронны, кнопка операции меняется на «Отмена», общий лимит 5 минут, сетевой таймаут 60 секунд. Принятие SMTP-сервером не гарантирует доставку в ящик.

TLS 1.2/1.3, стандартная проверка сертификата и имени хоста, без автоматического перехода к открытому тексту. Логи отображают только этап операции, тип ошибки и SMTP status code, без сырого сетевого диалога. Старые секреты следует отозвать; предыдущая история Git не переписана.

## Ручной smoke test

1. Отправить через SMTP 587/STARTTLS и 465/SSL; кириллица, несколько вложений.
2. Получить по POP3 995, IMAP 993; проверить тему, отправителя, тело и вложения, отсутствие признака прочтения у ранее непрочитанного IMAP-письма.
3. Проверить неверный пароль, недоверенный сертификат, сервер без STARTTLS и отмену подключения.
4. Сохранить одно вложение дважды: второй файл получает числовой суффикс.
5. Убедиться, что пароли не появляются в UI-журнале и что отмена не вызывает зависание.
6. При необходимости проверить relay без AUTH на собственном тестовом сервере.

Локальная сборка/сетевой smoke test выполняются на Windows. Полноценный протокольный журнал с редактированием секретов будет отдельным этапом.

### Мониторинг

Добавьте профиль в разделе «Мониторинг»: имя (например, Company A / SMTP), тип, целевой адрес, интервал. Профили по расписанию выключены при создании; поставьте «Активен» и нажмите «Вкл. расписание» для выполнения в открытом GUI. «Запустить» запускает выбранный профиль вручную (в том числе выключенный). Редактирование доступно для незанятых профилей; удаление удаляет историю. После завершения новый срок = текущее время + интервал. Не запускаются все пропущенные проверки задним числом.

| Проверка | Интервал по умолчанию |
| --- | --- |
| HTTP GET без редиректов, TCP, Mail (SMTP/POP3/IMAP TLS, AUTH опционально) | 5 мин |
| DNS/MX | 60 мин |
| SPF/DKIM/DMARC (записи), DNSBL | 360 мин |
| Сертификат, RDAP/WHOIS | 1440 мин |
| Round Trip | 15 мин (минимум 15 мин) |

SQLite: `%LOCALAPPDATA%\\MailTester\\monitor.db`; WAL, история 90 дней (удаление старых записей при завершении проверки), последние 100 в GUI, CSV-экспорт и график (до 50 последних проверок). Состояния OK, Warning, Error, Unknown; дата и экранные значения могут отличаться по часовому поясу, отчёт истории UTC. Это история наблюдений, не точная непрерывная доступность. GUI проверяет очередь каждые 15 с, выполняет по одной задаче, откладывает запуск при активной ручной операции. SQLite выдаёт атомарную аренду профиля на 10 минут, обычный бюджет проверки 4 минуты; аварийное завершение может оставить аренду до её истечения. Несколько процессов могут проверять разные профили; одна и та же задача не выполняется одновременно в нормальных условиях. Профиль не активируется автоматически после перезапуска GUI. Регулярному запуску CLI требуется отдельный Планировщик заданий Windows.

Пароли сохраняются как DPAPI CurrentUser ciphertext; остальная конфигурация (в т.ч. логин, адрес, имя, URL без query) и диагностические данные хранятся локально в SQLite без шифрования. Профиль не переносит пароли автоматически на другую учётную запись/ПК. Не передавайте БД третьим лицам. Никакого Telegram, облачного журнала или телеметрии. DNSBL/RDAP/WHOIS неизбежно обращаются к выбранным внешним источникам. Пароли не выдаются в CLI и CSV.

### Round Trip

Создайте профиль RoundTrip с SMTP, тестовым отправителем и получателем, IMAP/POP3, TLS и паролями приложения. Используйте выделенный тестовый почтовый ящик. Для одной проверки MailTester проверяет доступ к ящику, отправляет одно реальное письмо с новым X-MailTester-ID, ищет его через IMAP SEARCH + заголовки в INBOX или до 100 последних POP3-заголовков. Таймаут ожидания 15–180 с, опрос 5–30 с. Результат: Delivered, NotObserved, SendUnknown, SendFailed, ReceiveFailed; обнаружение включает задержку опроса и не является точным временем серверной доставки. Если почтовый фильтр удалил X-MailTester-ID/перенёс письмо из INBOX или POP3-окно уехало, результат может быть NotObserved даже при доставке. Не удаляет письма и не повторяет отправку при неполучении; настроить очистку выделенного ящика на сервере. При отмене во время отправки статус может быть неизвестен. 15-минутный профиль создаёт до 96 писем/сутки. Не запускайте на чужих ящиках и не используйте для массовой отправки.

### CLI и внешние системы

После публикации в PowerShell:

```powershell
$cli = ".\\artifacts\\cli-win-x64\\MailTester.Cli.exe"
& $cli dns example.com --json
& $cli dns-records example.com
& $cli spf example.com --ip 192.0.2.10 --from test@example.com
& $cli dkim example.com --selector mail
& $cli dmarc example.com
& $cli whois example.com
& $cli tls example.com --port 443
& $cli audit example.com --json
& $cli monitor list
& $cli monitor run-due --max 20 --json
& $cli monitor history <PROFILE_ID> --format csv
& $cli monitor status <PROFILE_ID> --format zabbix
& $cli monitor latency <PROFILE_ID> --format zabbix
& $cli roundtrip <PROFILE_ID> --json
```

Замените placeholder PROFILE_ID на ID из monitor list (кавычки и реальные символы вместо угловых скобок). Форматы text/json/csv/zabbix; обычные exit codes 0 OK, 1 Warning, 2 Error, 3 Unknown/ошибка CLI/отмена. Zabbix format печатает числовой статус и возвращает exit 0 для результата (3 при ошибке самого CLI). Для latency успешный последний результат: секунды, иначе -1; срок свежести = два интервала. Не храните пароли в UserParameter. CLI list не содержит защищённых blob. Не запускать roundtrip из Zabbix каждую минуту: планировщик заполняет историю, Zabbix читает status/latency. Для фоновой проверки при закрытом GUI установите задачу отдельно (под тем же Windows-пользователем, вошедшим в систему):

```powershell
.\\scripts\\install-monitor-task.ps1 -CliPath ".\\artifacts\\cli-win-x64\\MailTester.Cli.exe"
# Удаление задачи:
Unregister-ScheduledTask -TaskName "MailTester Monitor" -Confirm:$false
```
Задача запускается раз в минуту, не запускает новый экземпляр если предыдущий ещё работает, и не требует администраторских прав при разрешении политикой Windows. Интерактивная задача требует активной пользовательской сессии; после выхода из Windows мониторинг не работает. Для режима без входа в систему отдельно настройте задачу с профилем нужной Windows-учётной записи и проверьте DPAPI. Установщик автоматически задачу не регистрирует.

### Локальные тесты

`SecuritySmoke` проверяет DPAPI, сохранение шифрованного профиля и историю в временной SQLite, атомарную аренду, выключенные задачи, корреляцию X-MailTester-ID. Реальные сетевые тесты RoundTrip, SSL, RDAP и работа GUI требуют Windows, контролируемых SMTP/IMAP/POP3 и DNS. Проверьте отсутствие предупреждений у зависимостей: `dotnet list Cli/MailTester.Cli.csproj package --include-transitive --vulnerable`.
